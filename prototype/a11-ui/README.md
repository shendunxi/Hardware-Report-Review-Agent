这是方案 A「流程工作台」的旧版原生 JavaScript 对照实现，保留用于回归验证和 Vue 构建缺失时的兜底。正式入口现由 `frontend/` 下的 Vue 3 应用提供；本目录不再作为默认页面。

## 真实路径：完成并重新打开审核

1. 在“审核工作台”点击“创建审核任务”。
2. 从当前已发布版本中选择审核模板；任务创建后会冻结该版本和规则集合。
3. 选择一份主报告；可再选择多份支撑材料，并为每份材料至少标注一种证据类型。
4. 点击“创建并开始审核”，等待解析和规则审核完成。
5. 在任务进度页点击“进入人工复核”。
6. 选择系统初判为“符合”的 TR-01，将人工最终状态改为“不符合”，填写修改原因，并将选填的补充证据留空。任一已执行项都允许人工复核系统初判；修改原因必填，补充证据选填。
7. 筛选“待人工确认”，选择 TR-16，填写修改原因并选择三种最终状态之一，解决待人工确认项。
8. 待人工确认项清零后点击“完成审核”，完成第 1 次审核。
9. 点击“导出正式审核副本”，预览第 1 次审核的 D/E/F/G 映射；关闭预览后点击“重新打开审核”。
10. 修改一个人工结论并再次完成，形成保留前一快照的第 2 次审核。

## 真实路径二：模板规则管理维护模板

1. 使用页面右上角角色选择器切换到“模板规则管理”。
2. 从左侧进入“模板管理”，上传版本字段与工作表 A2 一致的 A11 派生 XLS。
3. 打开待发布版本，编辑、启用、停用、新增或删除校验项。
4. 查看结构阻塞项和非阻塞发布提醒；存在结构阻塞时不能发布。
5. 确认缺少自动判定条件的规则不会阻止管理员制定规则，而会标记为“需人工复核”。
6. 结构校验通过后点击“发布版本”；已发布版本只读，可执行停用。

## 审核状态边界

- 审核过程状态为：符合、不符合、不适用、待人工确认。
- 明确要求的必需证据未上传时仍判为“不符合”。
- 材料已提供，但规则和 AI 均无法形成明确证据结论时进入“待人工确认”。
- 任一已执行项都可由具备审核权限的角色改判，且保留系统初判；修改原因必填，补充证据选填。
- 所有待人工确认项必须经人工转为三种最终状态之一，才能完成审核、打开导出预览或重新进入下一次修订。

## 角色权限

- “测试报告审核”角色可以创建任务、复核和完成审核，但不能进入或修改模板规则。
- “模板规则管理”角色可以创建草稿、启停规则和发布版本，但不能编辑审核结果、完成审核或导出预览。
- 组合角色同时看到审核流程与模板规则两组导航，并拥有两组权限。

## 当前能力边界

- 上传入口支持 PDF · DOC · DOCX · XLS · XLSX。默认真实模式会上传文件并调用本机服务；XLS、PDF 和 DOC 适配器已接入执行链路。PDF 已有真实样本证据；DOC 在缺少 genuine Microsoft Word 时会返回可诊断失败，当前主机上的真实 DOC 门禁仍为 NO-GO，不能把 WPS 视为 Word 验收证据。DOCX/XLSX 尚无真实样本，不能声明兼容通过。
- 已完成审核可从真实任务详情或审核页下载任务绑定版本的 A11 XLS 副本；原报告和源模板不会被覆盖。
- 管理员后续停用模板不会改变已创建任务；没有确定自动实现的新增或改写规则会进入“待人工确认”，不会套用旧规则生成结论。
- 真实模式的任务、审核事实、模板草稿、任务规则快照和发布状态保存在开发用 SQLite；生产数据库尚未确定。角色切换仍是页面模拟。
- `?mode=demo` 下的任务、角色、草稿和审核修订仅保存在当前页面内存中，刷新页面后会重置。

## 文件说明

- `index.html`：页面入口和语义结构。
- `styles.css`：桌面端视觉样式、状态颜色和 1280px 宽度适配。
- `demo-data.js`：A11 的 22 个源行、21 个执行项及演示任务数据。
- `api-client.js`：任务审核和模板管理接口的同源客户端。
- `app.js`：真实模式、显式演示模式、轮询和页面交互。
- `tests/prototype.test.js`：结构和需求契约测试。
