## 1. 背景与问题定义

### 1.1 现状

- [你说的] 当前由人工审核硬件测试报告，单份约需 4 小时，每年预计审核 1000 份以上。
- [你说的] 当前主要问题包括模板不规范、结论与数据不一致、关键附件或截图缺失、测试项遗漏、版本信息不完整、风险描述不充分。
- [你说的] 当前审核错误率约为 10%；上线后的统计以系统初判和人工最终判定的差异为依据。
- [你说的] 正式审核模板为 A11。源文件修订记录中的 `A111` 是笔误，不构成新版本。
- [你说的] 当前提供 17 个报告文件，其中 12 个 XLS、2 个 DOC、3 个 PDF；两组 DOC/PDF 为同一报告的不同格式，因此对应 15 份独立报告。

### 1.2 痛点（按严重度排序）

1. [你说的] 审核耗时高：单份约 4 小时，按每年 1000 份计算约消耗 4000 小时。
2. [你说的] 漏项或错判：报告可能缺少测试项、版本信息、附件、截图或充分的风险描述。
3. [你说的] 证据不可追溯：检查结论缺少对应页码、单元格、附件或模板要求，复核者无法重复定位。
4. [你说的] 结论与原始数据可能不一致，依赖人工逐项比对。
5. [你说的] 历史已填写检查表本身存在问题，不能直接作为正确答案或训练金标准。

### 1.3 不做的代价

- [你说的] 继续保留约 4 小时/份的审核耗时和约 10% 的现有错误率。
- [我推断的] 按每份节省 3.5 小时计算，无法释放预计约 3500 小时/年的审核工时。
- [我推断的] 缺失证据和审核依据将继续依赖个人经验，无法形成可复核的统一记录。

### 1.4 为什么是现在

- [你说的] 每年存在 1000 份以上的稳定审核需求，节省工时的规模已经明确。
- [你说的] A11 模板及 17 个真实报告文件已经可以作为首批规则拆分和兼容性验证材料。

本节回答了“当前问题是什么、影响多大、为何需要现在处理”。

## 2. 目标与非目标

### 2.1 业务目标

| 目标 | 基线 | 目标值 | 统计口径 |
|---|---:|---:|---|
| [你说的] 单份审核总时长 | 约 4 小时 | P95 ≤20 分钟 | 从材料上传完成并开始审核，到待人工确认项全部解决且审核完成；包含自动处理和人工复核 |
| [你说的] 试运行审核差异率 | 约 10% | ≤5% | 系统初判与人工最终状态不同的执行项数 ÷ 全部经人工查看的执行项数 |
| [你说的] 试运行漏检率 | 当前未单独统计 | ≤5% | 人工最终判为不符合、但系统初判为符合或不适用的执行项数 ÷ 人工最终判为不符合的执行项数 |
| [你说的] 每年节省工时 | 0 | 约 3500 小时 | 年审核份数 × 单份节省 3.5 小时 |
| [你说的] 不符合项依据覆盖率 | 未统一记录 | 100% | 每条系统初判“不符合”必须有报告/附件定位，或模板要求与缺失材料清单 |
| [我推断的] 自动判定覆盖率 | 未统计 | ≥90% | 首次自动审核得到符合、不符合或不适用的执行项数 ÷ 全部执行项数 |
| [我推断的] 待人工确认占比 | 未统计 | ≤10% | 首次自动审核为待人工确认的执行项数 ÷ 全部执行项数 |
| [你说的] 源文件修改次数 | 人工流程未统一统计 | 0 | 原报告和源模板不得被覆盖或写回 |

[我推断的] “差异率 ≤5%”“自动判定覆盖率 ≥90%”“待人工确认占比 ≤10%”属于真实业务试运行指标，不作为缺少人工金标准情况下的上线前虚假通过条件。上线前使用第 5 节所列硬门槛。

### 2.2 用户目标

- [你说的] 模板规则管理能够上传、检查、编辑、发布、停用 A11 派生模板及其校验项。
- [你说的] 测试报告审核能够选择已启用模板创建任务，上传报告和证据，查看逐项初判及依据。
- [你说的] 测试报告审核能够把任一系统初判改为符合、不符合或不适用；修改原因必填，补充证据不强制。
- [你说的] 所有待人工确认项必须被人工处理后才能完成审核。
- [你说的] 系统生成新的已填写 XLS 审核模板副本供参考，不修改原报告或源模板。

### 2.3 非目标

- [你说的] M1 不修改、覆盖或回写原测试报告和源模板。
- [你说的] M1 不提供“无法判断”或“接受例外”结果状态。
- [你说的] M1 不设置问题严重性或风险等级。
- [你说的] M1 不以历史已填写 A10/A11 检查表作为正确答案。
- [你说的] M1 不直接连接 JIRA 或共享目录，只接收任务随附的导出件、截图或文件。
- [我推断的] M1 不执行上传文件中的宏、外链程序或嵌入程序。
- [我推断的] 系统内审核完成不等于最终业务放行；系统外仍可进行人工证明验收。

## 3. 目标用户与使用场景

### 3.1 用户画像

| 角色 | 当前替代方式 | M1 权限 |
|---|---|---|
| [你说的] 测试报告审核 | 人工打开报告、模板和附件逐项核对 | 创建任务、上传材料、查看结果、修改任一初判、完成审核、导出副本 |
| [你说的] 模板规则管理 | 人工维护 XLS 检查表 | 上传模板、检查解析结果、新增/删除/停用校验项、发布/停用版本 |

- [你说的] 同一账号可以同时拥有两个角色，权限取并集。
- [你说的] 只有具备“测试报告审核”权限的账号可以修改审核结果；仅具备“模板规则管理”权限不能修改。

### 3.2 核心场景（按频率排序）

1. [你说的] 测试报告审核选择已启用模板，上传一份 PDF、DOC、DOCX、XLS 或 XLSX 主报告及所需证据，创建审核任务。
2. [你说的] 系统先执行客观规则，再对涉及语义判断的项目调用已获授权的大语言模型；两者均无法形成明确证据时进入待人工确认。
3. [你说的] 测试报告审核查看系统初判和可追溯依据，可把任一项改为三个最终状态之一并填写修改原因。
4. [你说的] 测试报告审核处理完全部待人工确认项后完成审核；未修改项隐式接受系统初判，无需逐项点击。
5. [你说的] 完成后导出新的 XLS 审核副本；若需再次修改，重新打开审核并形成新修订版，保留历史版本。
6. [你说的] 模板规则管理上传模板，审核系统识别出的 22 个源行，并在发布前维护 21 个实际执行项。

本节回答了“谁在什么流程中使用产品、各角色能做什么”。

## 4. 功能需求

### FR-01 模板上传与结构校验

- 作为模板规则管理，我希望上传 XLS 模板并看到结构解析结果，以便确认其可被系统使用。
  - 验收标准：
    - Given 用户具备模板规则管理权限 / When 上传结构符合 A11 基线的 XLS / Then 系统显示模板版本、22 个源行、21 个执行项及非阻塞警告。
    - Given 上传文件无法读取或缺少必需工作表/固定区域 / When 执行结构校验 / Then 系统拒绝发布并指出可定位的结构问题。
  - 优先级：Must

### FR-02 规则维护与版本发布

- 作为模板规则管理，我希望新增、删除、停用校验项并发布新版本，以便维护审核标准。
  - 验收标准：
    - Given 模板处于未发布状态 / When 用户修改校验项 / Then 修改只影响该待发布版本并留下操作者和时间记录。
    - Given 规则缺少判定依据但结构合法 / When 用户发布 / Then 系统给出会增加待人工确认的警告但不阻止发布。
    - Given 版本结构校验失败 / When 用户发布 / Then 发布被阻止且当前已启用版本不受影响。
  - 优先级：Must

### FR-03 创建审核任务与上传材料

- 作为测试报告审核，我希望选用已启用模板并上传报告和证据，以便创建审核任务。
  - 验收标准：
    - Given 存在已启用模板 / When 上传 PDF、DOC、DOCX、XLS 或 XLSX 主报告并提交 / Then 系统创建与该模板版本绑定的任务。
    - Given 文件受密码保护、受保护且无法读取或格式损坏 / When 提交 / Then 系统拒绝该文件并显示失败原因。
    - Given 上传文件含宏、外链或嵌入程序 / When 系统读取 / Then 这些内容不被执行。
  - 优先级：Must

### FR-04 客观规则审核

- 作为测试报告审核，我希望系统优先执行可确定的客观规则，以便得到可重复验证的初判。
  - 验收标准：
    - Given 规则具备明确字段、格式、数值或适用性条件 / When 审核执行 / Then 系统输出初判状态、命中的规则要求和证据位置。
    - Given 规则明确要求外部证据且任务未上传 / When 审核执行 / Then 系统初判为“不符合”，并列出缺失材料与规则要求。
  - 优先级：Must

### FR-05 语义审核

- 作为测试报告审核，我希望语义类规则调用获授权的大语言模型，以便检查结论与数据、问题描述等语义关系。
  - 验收标准：
    - Given 客观规则不能完成语义判断且 API 和数据范围已获授权 / When 执行语义审核 / Then 系统输出带可重复定位证据的初判或待人工确认。
    - Given API 未授权或该数据不允许外发 / When 任务包含语义规则 / Then 内容外发次数为 0，相关项不能被宣称已完成自动审核。
    - Given 模型不能形成明确证据 / When 返回审核结果 / Then 系统不得猜测页码、单元格或附件名称，并将该项设为待人工确认。
  - 优先级：Must

### FR-06 逐项结果与证据展示

- 作为测试报告审核，我希望查看每个执行项的状态和依据，以便复核系统判断。
  - 验收标准：
    - Given 审核已产生结果 / When 打开结果页 / Then 每项展示系统初判、判定来源、规则要求和证据或缺失材料。
    - Given 某项初判为不符合 / When 查看详情 / Then 至少存在一个可追溯的报告/附件位置，或“模板要求+缺失材料+检查范围”。
  - 优先级：Must

### FR-07 人工修改任一初判

- 作为测试报告审核，我希望把任一系统初判改为符合、不符合或不适用，以便最终结果以人工判断为准。
  - 验收标准：
    - Given 用户具备测试报告审核权限且任务未完成 / When 修改任一项状态 / Then 目标只能是符合、不符合或不适用，修改原因必填，补充证据可选。
    - Given 修改已提交 / When 再次查看该项 / Then 系统同时保留初判、人工最终状态、原因、操作者和时间，不覆盖初判历史。
    - Given 用户仅具备模板规则管理权限 / When 尝试修改结果 / Then 操作被拒绝。
  - 优先级：Must

### FR-08 完成审核

- 作为测试报告审核，我希望完成无需逐项点击确认的审核，以便减少重复操作。
  - 验收标准：
    - Given 仍存在待人工确认项 / When 用户尝试完成审核 / Then 操作被阻止并显示剩余数量。
    - Given 待人工确认项为 0 / When 用户完成审核 / Then 未修改项的最终状态等于系统初判，已修改项采用人工最终状态，并生成不可直接覆盖的完成版本。
  - 优先级：Must

### FR-09 重新打开与修订历史

- 作为测试报告审核，我希望重新打开已完成审核并形成新修订版，以便纠正结果且保留历史。
  - 验收标准：
    - Given 审核已经完成 / When 用户选择重新打开 / Then 系统创建新的结果修订版，先前完成版本仍可查看且不可被覆盖。
    - Given 新修订版再次完成 / When 查看历史 / Then 可查看每版状态、修改原因、操作者和完成时间。
  - 优先级：Must

### FR-10 导出审核模板副本

- 作为测试报告审核，我希望导出由系统填写的 XLS 副本，以便在线下查看和验收。
  - 验收标准：
    - Given 审核已完成 / When 导出 / Then D/E/F 写入最终三状态；G 写入系统依据，并在发生人工修改时附加人工修改原因。
    - Given 未发生人工修改 / When 导出 / Then 该项使用系统初判作为最终状态。
    - Given 执行导出 / When 比对源报告和源模板 / Then 二者内容及时间戳均未因导出被修改。
  - 优先级：Must

本节回答了“工程团队需要交付哪些可验收的用户能力”。

## 6. 约束与依赖

### 6.1 已有系统、接口和材料

- [你说的] A11 XLS 模板是当前规则基线；22 个可见源行中序号 5 并入序号 4，实际执行 21 项。
- [你说的] M1 对 JIRA、共享目录和纸质记录仅处理随任务上传的导出件、截图或文件，不直接集成。
- [你说的] 历史 A10/A11 已填写检查表仅用于了解历史行为，不作为期望标签。

### 6.2 环境与合规

- [你说的] M1 输入格式为 PDF、DOC、DOCX、XLS、XLSX；模板及导出格式为 XLS。
- [你说的] 大语言模型不取消，但只有在 API、数据范围和留存方式获授权后，才可完成语义审核验收。
- [你说的] 未获授权时不得把报告内容发送到外部服务。
- [你说的] 扫描型 PDF 只有在当前或补充样本能够稳定读取后才纳入支持声明。

### 6.3 项目约束

- [待确认] 交付期限、研发人数、测试人数和预算尚未提供。默认处理：本轮只冻结范围；下一阶段完成工作量估算后再承诺里程碑日期，否则不能证明 Must 能在指定周期内完成。
- [待确认] 公司数据保留制度、实际 Office/WPS 版本、获授权的大模型 API 尚未提供。默认处理采用第 5 节临时值；正式上线前必须由对应负责人替换或签字接受。

### 6.4 不可控因素
