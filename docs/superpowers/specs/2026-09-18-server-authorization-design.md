# 服务端角色授权设计

日期：2026-09-18  
状态：已确认

## 1. 目标与边界

本切片把现有前端角色演示升级为服务端强制授权，覆盖“测试报告审核”“模板规则管理”和二者权限并集。开发环境继续允许本机切换角色；生产身份提供方、组织账号同步和单点登录不在本切片内，未接入真实身份提供方前不得声明生产认证完成。

本切片不修改审核业务规则、模板状态规则、报告解析器、导出格式或数据库结构，也不新增测试用例。

## 2. 推荐架构

后端新增统一的访问上下文和身份提供方边界。路由只依赖已验证的访问上下文，不直接读取任意角色请求头，也不信任表单中的操作者名称。

开发模式提供仅限回环地址使用的本地会话接口。用户选择角色后，服务端签发带完整性保护的 HttpOnly、SameSite=Strict 会话 Cookie；后续请求由服务端验证 Cookie 并恢复操作者及角色集合。Cookie 内容被篡改、过期或缺失时返回 401，角色不足时返回 403。

生产模式保留身份提供方接口，但本切片不伪造 OIDC、LDAP 或企业 SSO。生产模式若没有配置真实验证器，应拒绝启动或拒绝受保护请求。

## 3. 权限矩阵

| 操作 | 测试报告审核 | 模板规则管理 |
|---|---:|---:|
| 读取已发布模板列表和详情 | 允许 | 允许 |
| 创建、查看、执行审核任务 | 允许 | 拒绝 |
| 人工改判、完成、重开、导出 | 允许 | 拒绝 |
| 上传模板 | 拒绝 | 允许 |
| 新增、修改、删除模板规则 | 拒绝 | 允许 |
| 发布、停用模板版本 | 拒绝 | 允许 |

组合角色取两组权限并集。

## 4. 操作者与审计

人工改判操作者由访问上下文写入，替代当前硬编码的 `local-review`。模板上传的 `created_by` 同样来自访问上下文；前端不再提交可自行填写的 `actor` 字段。模板发布、停用及规则变更由服务端强制检查管理权限，但现有数据模型没有对应操作者审计字段；本切片不改数据库结构，因此这部分完整审计继续列为上线 NO-GO，不得宣称已完成。

已有历史记录保持不变，不回填或改写旧操作者字段。

## 5. 前端行为

当前角色选择器在开发模式下调用本地会话接口，成功后再更新页面权限和路由。所有 API 请求携带同源 Cookie；导出链接也依赖同一会话。401 显示“会话未建立或已失效”，403 显示“当前账号没有此操作权限”。

前端权限仅用于隐藏入口和改善导航体验，最终授权结论始终由服务端决定。

## 6. 错误与安全边界

- 未认证：HTTP 401，稳定代码 `AUTHENTICATION_REQUIRED`。
- 角色不足：HTTP 403，稳定代码 `PERMISSION_DENIED`。
- 本地会话接口收到非回环来源：HTTP 403，且不签发 Cookie。
- 会话密钥不得写入前端构建产物；开发默认值只允许用于回环地址。
- 不接受客户端提交的角色、操作者或权限作为审计事实。

## 7. 验证方式

遵循“不新增测试用例”的约束：调整既有测试客户端以建立本地会话，运行现有后端、前端、类型检查和生产构建；另外使用真实 HTTP 请求手工验证 401、403、审核角色、模板角色和组合角色的权限边界。生产认证门禁保持 NO-GO。
