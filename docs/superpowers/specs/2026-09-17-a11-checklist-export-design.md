## 1. 目标与边界

- [你说的] 审核结束后可导出一份由系统填写的测试检查表副本。
- [你说的] 不修改原测试报告，不覆盖原 A11 模板；人工最终状态优先于系统初判。
- [你说的] 最终状态仅允许“符合、不符合、不适用”；“待人工确认”未全部处理时不得完成，因而不得导出。
- [我推断的] M1 只支持已固化的 A11 `.xls` 模板；不在本次实现管理员上传和发布模板的真实后端。

## 2. 权威模板与安全性

- 以用户提供的《硬件测试过程检查单.xls》为 A11 权威模板，复制到应用受控资源目录。
- 运行时只读模板并在内存中生成新工作簿，不向模板路径写入。
- 导出前校验工作表“硬件测试过程检查表”、版本单元格 `A2=A11`、以及 21 个启用规则的源行。
- 文件名仅使用安全化的报告名、`A11`、审核修订号；响应不暴露服务器内部路径。

## 3. 回写映射

| 业务值 | 模板列 | 写入值 |
|---|---|---|
| 最终状态=符合 | D | `√` |
| 最终状态=不符合 | E | `╳` |
| 最终状态=不适用 | F | `⊙` |
| 审核说明 | G | 系统判定依据、可追溯证据/缺失材料、人工修改原因 |

- 每个启用规则使用 `A11Registry.source_row` 定位 Excel 行。
- 写入前先清空该行 D:F，再且只写入一个最终标记。
- TR-05 是禁用源行，不写入任何审核结果。
- G 列使用中文标签分段：`系统判定依据`、`可追溯证据`、`缺失材料`、`人工修改原因`；没有的段不写。

## 4. 生命周期与 API

- `GET /api/tasks/{task_id}/export`只接受 `COMPLETED` 任务。
- 导出使用最新的不可变 `ReviewRevision.result_snapshot`，不从当前界面状态重新推导。
- 任务重新打开后状态变为 `READY_FOR_REVIEW`，导出接口返回 `INVALID_TASK_STATE`；再次完成后使用新修订快照导出。
- 成功响应为 `application/vnd.ms-excel`，并提供 UTF-8 文件名的 `Content-Disposition: attachment`。
- 模板不可用或快照损坏时返回稳定错误码，不返回半成品文件。

## 5. 前端

- 真实 API 模式的已完成任务顶部同时显示“导出测试检查表”和“重新打开审核”。
- 导出控件是同源下载链接，只在 `COMPLETED` 状态渲染。
- 演示模式的“原型预览”行为保持不变，不冒充真实导出。

## 6. 验收证据

1. 非完成任务请求导出返回 409 及 `INVALID_TASK_STATE`。
2. 已完成任务返回可由 `xlrd` 重新打开的 `.xls`。
3. 21 个启用规则的 D/E/F 与最终状态一致，TR-05 不被覆盖。
4. G 列包含中文系统依据和可追溯证据；有人工改判时包含必填修改原因。
5. 导出前后权威模板 SHA-256 不变。
6. 已完成任务页可见真实导出入口，非完成状态不可见。

本设计回答了何时允许导出、导出什么、哪些单元格被写入，以及如何证明没有修改源模板。
