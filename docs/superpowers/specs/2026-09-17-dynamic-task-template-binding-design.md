# Dynamic task-template binding design

## Scope

- [你说的] 测试报告审核从已发布模板中选择一个版本创建任务。
- [你说的] 管理员后续停用模板，不得改变已创建任务的审核依据。
- [你说的] 规则和大模型均不能形成明确证据时，结果进入“待人工确认”。
- [我推断的] 本切片把模板版本和规则内容冻结到任务；不在本切片接入生产大模型 API。

## Binding contract

1. 创建接口必须提交 `template_id`，且该版本当时必须为 `PUBLISHED`。
2. 任务保存模板 ID、名称、版本、源文件路径与哈希，以及当时所有规则的 JSON 快照。
3. 任务创建后只读取自己的规则快照；模板随后停用不影响执行、复核、重开和导出。
4. 旧数据库中的任务迁移为内置 A11 快照，保持兼容。

## Execution contract

- 快照中启用且仍与固化 A11 自动规则定义一致的规则，继续使用已验证的 A11 规则实现。
- 被停用的规则不生成结果。
- 管理员新增或改写、但没有对应确定执行器的规则，不套用旧逻辑，生成带模板要求的 `NEEDS_REVIEW` 结果。
- 每个结果集合必须与任务快照中的启用规则 ID 精确一致，不再硬编码为 21 项。

## Export contract

- 导出读取任务冻结的模板路径、哈希和规则快照，不读取“当前已发布模板”。
- 已有来源行的结果写回该来源行；无来源行的逻辑规则在副本末尾追加行。
- 导出只允许最终三状态，并继续使用最新不可变完成快照。
- 若任务绑定模板已被替换、丢失或哈希改变，返回稳定错误，不生成半成品。

## Explicit non-goals

- 不实现登录与服务端角色鉴权。
- 不接入大语言模型供应商或生产数据库。
- 不把自然语言规则自动编译为程序规则。
- 不改变原报告或模板源文件。
