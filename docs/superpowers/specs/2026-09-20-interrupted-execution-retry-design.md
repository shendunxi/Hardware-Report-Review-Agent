# 中断执行的可重试入口设计（S1e）

日期：2026-09-20
状态：已确认

## 1. 目标与边界

闭合 S1 明确声明的遗留缺口：S1 已让服务端在租约到期后可以重新认领中断的执行，但**前端没有任何触发 `execute` 的入口**（`TaskDetailView` 只轮询 `GET`），用户只能看到任务停在中间态并**无限轮询**，恢复必须由 API 手工触发。

**不涉及**：自动重试、租约时长调整、任务状态机、审核规则、导出格式、数据库结构。

## 2. 关键设计决策

### 2.1 手动按钮，不做自动重试

| 方案 | 优点 | 缺点 | 采纳 |
|---|---|---|---|
| 客户端自动重试 | 无需用户操作 | ① 崩溃可能是**永久性**的（该文件在该解析器下必然失败），自动重试会反复消耗解析资源；② 租约上限默认 30 分钟，用户离开页面后自动触发超出预期；③ 失败原因被自动行为掩盖 | ✗ |
| **手动「重新执行」** | 可预测、可解释，失败路径由用户显式触发 | 需要用户点一下 | ✓ |

选择手动。与项目「不臆造、不替用户做判断」的文化一致。

### 2.2 可重试性由**服务端派生**，前端不复算

前端已知 `state` 与 `updated_at`，若再引入租约时长就能自行推算——但那样会把租约语义复制进 TypeScript，正是代码评审中已点出的重复模式（`review.ts` ↔ `a11_export.py` 的双份文案）。因此由服务端在任务载荷中下发派生字段。

**契约**：`ReviewTask.execution`

```ts
execution: { reclaimable: boolean; seconds_until_reclaimable: number } | null
```

| 值 | 含义 |
|---|---|
| `null` | 任务不在被中断的中间态（正常流转或已到终态） |
| `{reclaimable: false, seconds_until_reclaimable: N}` | 处于 `{FILES_STAGED, PARSING, PARSED, EVALUATING}`，租约未到期，还有 N 秒 |
| `{reclaimable: true, seconds_until_reclaimable: 0}` | 租约已到期，`POST /execute` 会真正启动执行 |

**唯一实现**放在 `LifecycleService.execution_status(task)`；`inspect_interrupted()` 改为复用同一计算（消除重复）。

### 2.3 为什么不改用状态码表达

`POST /api/tasks/{id}/execute` 现在无论是否真正认领都返回 `202`。改成 `409` 会破坏既有幂等语义——对 `READY_FOR_REVIEW` 任务重复调用 `execute` 是合法的无操作（`createAndExecute` 与重试路径都依赖它）。因此**保持 202**，改由载荷字段让前端判断按钮可用性。

## 3. UI 行为

`TaskDetailView` 在 `task.execution !== null` 时显示「执行已中断」面板：

- `reclaimable === true` → 「重新执行」按钮**可用**；点击调用 `POST /execute` 后重载任务
- `reclaimable === false` → 按钮**禁用**，提示「需等待执行租约到期后再重试（约 X 分钟）」
- 既有的 2 秒轮询会让 `seconds_until_reclaimable` 自然递减，**无需额外计时器**
- 重试成功后 `state` 离开被中断集合，面板自动消失

按钮仅在服务端声明可重认领时启用，避免出现「点了没反应」。

## 4. 错误与安全边界

- 对外错误码**零变更**
- 不引入自动重试，不新增任何写路径
- 前端权限仅影响入口可见性；最终授权结论仍由服务端决定（沿用既有原则）
- 复用既有 `.failure-panel` / `.button-row` 样式，不新增 CSS 类

## 5. 验证方式

硬约束：不新增测试文件或测试用例，只扩展既有测试的断言。

| 目标 | 位置 |
|---|---|
| 载荷派生字段随租约变化 | `tests/integration/test_lifecycle.py`（在 S1 已有的租约断言段落内继续断言） |
| store 的 `reexecute` 先调 execute 再重载 | `frontend/src/stores/tasks.spec.ts` 的既有用例 |
| 视图渲染 | **自动化未覆盖**（仓库无 `TaskDetailView` spec，且不允许新增用例）→ 以 `vue-tsc` + 生产构建 + 构建产物文案检查 + **人工浏览器确认**为准 |

## 6. 缺口声明（必须随交付一起说明）

1. **视图层没有自动化测试**。因此不得以「测试通过」宣称视图已验收；只有人工浏览器确认才能关闭该项。
2. 本切片不缩短崩溃后的等待时间——用户仍可能在最坏情况下等待一个完整租约周期（默认 30 分钟）才能点击「重新执行」。缩短等待需要更细粒度的心跳或更短的租约，属后续议题。
3. 不做自动重试（§2.1）。
4. 不做租约时长的配置界面。
5. 不做任何 Git 操作。
