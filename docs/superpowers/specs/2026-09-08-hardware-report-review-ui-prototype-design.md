## 2. 原型目标与边界

原型用于验证页面信息架构、关键任务流、状态表达及 A11 模板规则的界面映射。演示者应能在不阅读说明文档的情况下，从工作台创建任务、查看四状态过程结果、完成人工复核并导出只含三种最终状态的审核副本；管理员应能完成模板查看、校验项维护和发布状态切换。

本轮原型不接入真实文件解析、大语言模型 API、账号认证或后端存储；上传、审核进度、导出等行为用可交互的演示状态表达。原型不修改或覆盖任何用户文件。

## 3. 导航与角色

采用统一左侧导航，顶部显示产品名称、当前角色与个人入口。

测试报告审核可见：

1. 审核工作台
2. 审核任务
3. 创建任务

模板规则管理额外可见：

1. 模板管理
2. 模板规则编辑

原型通过角色切换控件演示两类权限视图。测试报告审核不可见模板上传、发布、停用或规则增删入口；仅有模板规则管理权限的账号不能修改审核结果。同一账号可拥有两个角色，权限取并集。

## 4. 页面设计

### 4.1 审核工作台

- 显示待人工复核、审核处理中、本月已结束三个统计值。
- 最近任务列表显示报告名称、模板版本、进度或结果状态及更新时间。
- 主操作为“创建审核任务”。
- 待人工复核任务的视觉优先级高于处理中和已结束任务。

### 4.2 创建审核任务

采用单页分步表单，步骤为：

1. 选择已启用模板，默认示例为“硬件测试过程检查单 A11”。
2. 上传一份主测试报告，文件类型展示为 PDF、DOC、DOCX、XLS、XLSX。
3. 上传支撑证据，并按 JIRA、历史报告、原始记录、截图或其他附件分类展示。
4. 确认材料清单和缺失证据提醒后创建任务。

未上传主报告时“开始审核”不可用。缺少外部证据不阻止创建任务，但界面明确提示缺少必需证据的校验项将判为“不符合”。

### 4.3 审核任务详情

- 顶部显示任务名称、模板版本、创建人、创建时间和总体状态。
- 用时间线展示上传完成、规则审核、AI 审核、等待人工复核和任务结束。
- 审核完成前展示已完成执行项数和总执行项数；A11 总执行项为 21，不把仅存证据路径的序号 5 计入执行数。
- 失败状态提供可观察的失败原因及“重新审核”入口。
- 存在待人工确认项时任务状态为“待人工复核”；全部转为最终状态后才能执行“完成审核”。

### 4.4 审核结果与人工复核

采用三栏工作区：

- 左栏：22 个 A11 源行及筛选器；序号 5 标记为“证据地址/不独立执行”。
- 中栏：报告或附件证据预览区域，并突出当前证据位置。
- 右栏：当前校验项的判定、规则要求、证据引用和人工处理操作。

过程状态固定为：符合、不符合、不适用、待人工确认。界面不显示严重性、风险等级或自动通过结论。

每条不符合至少展示一条可追溯依据：报告或附件中的证据位置，或模板要求与缺失材料清单。明确要求的必需证据未上传时判为“不符合”；材料已提供，但规则和 AI 均不能形成明确证据结论时判为“待人工确认”。系统不得生成虚构页码、单元格或附件名称。

每个执行项均提供“修改判定”入口，目标状态只有符合、不符合、不适用。发生修改时原因必填、补充证据可选；提交后同时展示系统初判、人工最终状态、修改原因、复核人和复核时间，不覆盖初判。待人工确认项还须展示不能明确判定的原因，并必须逐项处理；存在任何未处理的待人工确认项时，“完成审核”和“导出正式审核副本”均不可用。其他初判不要求逐项点击，完成审核时隐式接受未修改状态。环境限制可作为人工修改原因，最终业务放行由系统外人工验收决定。

### 4.5 导出审核副本

- 导出前显示符合、不符合、不适用的数量汇总，不显示待人工确认写回列。
- 待人工确认项未清零时不能生成正式副本，并显示剩余待复核数量。
- 用户确认后生成独立的 A11 XLS 审核副本演示结果。
- D/E/F 采用人工最终状态；未改判时采用系统初判。G 保留系统依据，发生改判时附人工修改原因。
- 已完成结果不能直接覆盖；重新打开审核时创建新的修订版并保留先前版本。
- 界面使用“审核”，导出副本保留源模板中的“审计”文字。
- 原型明确展示“不会修改原测试报告”。

### 4.6 模板管理

- 列表显示模板名称、版本、源行数量、执行项数量、发布状态、创建人和更新时间；A11 对应 22/21。
- 管理员可进入上传、查看、编辑校验项、发布、停用操作。
- 已发布版本不直接覆盖；编辑入口在原型中表现为生成待发布版本。

### 4.7 模板规则编辑

- 左侧按源行列出 A11 校验项，显示规则编号、启用状态和判定方式。
- 主区域展示检查项原文、原子校验要求、所需证据、判定方式及导出映射。
- 支持新增、删除待发布版本中的校验项，以及启用或停用现有项。
- 发布前区分结构阻塞与规则提醒：规则编号重复、模板版本不一致等结构问题阻止发布；缺少自动判定条件、适用条件或证据定义只显示发布提醒，不阻止管理员制定或发布规则。
- 缺少自动判定条件的规则标记为“需人工复核”，任务执行时进入待人工确认。

## 5. 状态和视觉规范

- 页面基准尺寸为 1440×900，内容区域在 1280 像素宽时不得出现横向滚动。
- 采用深蓝灰企业后台风格，蓝色作为主操作色；文字与背景的常规对比度不低于 4.5:1。
- 状态不能只依赖颜色区分，必须同时显示文字或图标。
- 符合使用绿色，不符合使用红色，不适用使用灰色，待人工确认使用琥珀色。
- 主要操作按钮、筛选器、任务行、规则行和弹窗均提供悬停、选中、禁用或加载状态。
- 正文最小字号 14px；主要操作可见区域中的点击目标不小于 36×36px。

## 6. 核心演示路径

### 路径一：测试报告审核完成审核

工作台 → 创建任务 → 选择 A11 → 上传报告与证据 → 创建任务 → 查看审核进度 → 进入结果页 → 查看初判与依据 → 按需修改任一项并填写原因 → 逐项清零待人工确认 → 完成审核 → 导出正式审核副本；如需改动已完成结果则重新打开并生成新修订版。

### 路径二：管理员维护模板

切换模板规则管理 → 模板管理 → 打开 A11 → 查看结构校验 → 编辑校验项 → 生成待发布版本 → 发布或停用。

## 7. 原型验收标准

1. 从工作台开始，用户最多经过四次主操作即可创建审核任务。
2. 两条核心演示路径中的所有页面和主要按钮均可点击到达目标状态，不存在无反馈的主操作。
3. 结果页展示符合、不符合、不适用、待人工确认四种过程状态，且任一不符合示例都带有报告、附件或模板要求依据。
4. 缺少必需证据的校验项显示为不符合，并可观察到缺失材料及对应校验要求。
5. 材料已提供但规则和 AI 都不能形成明确证据结论的示例显示为待人工确认，且只能通过填写修改原因并选择三种最终状态之一完成处理。
6. 待人工确认项大于 0 时，完成审核和正式导出均不可用；清零后两项操作可用。
7. 导出确认区只汇总三种最终状态，明确显示目标为新建 XLS 副本，并明确不修改原报告。
8. 测试报告审核视图中不出现模板发布、停用或校验项增删操作。
9. 符合、不符合、不适用和待人工确认四种初判均可被测试报告审核修改；原因必填、证据可选，修改后仍能查看初判。
10. 完成审核时非待人工确认项无需逐项点击；已完成结果重新打开时产生新修订版。
11. 管理员视图展示 A11 模板、22 个源行、21 个执行项、结构阻塞和不会阻止发布的人工复核提醒。
12. 在 1440×900 和 1280×720 两种视口下，核心操作不被遮挡，页面无横向滚动。
