# 语义判定数据外发说明（OQ-06 答复材料）

本文件用于回答 PRD §9 的 **OQ-06**。它不是技术文档，而是一份**供签署的事实清单**：
把「启用语义判定后，究竟有哪些数据离开了本机、去了哪里、留多久」逐项写清楚。

**当前状态：本功能默认关闭（`HW_REVIEW_LLM_ENABLED=false`），未签署前不应在生产环境启用。**

## 1. 为什么需要签署

大模型判定要把报告内容发送到本机之外的 HTTP 端点。这在 PRD 里被登记为需要
**信息安全负责人 + 产品负责人**共同确认的开放问题（OQ-06），原因有三：

1. **外发是单向不可撤回的**：一旦发出，无法从对端撤回，只能依赖对端不留存。
2. **内容级别敏感**：报告含产品型号、项目名、测试人员姓名、缺陷描述。实测样本里可见
   「深圳创维数字技术有限公司」「测试人员：王思纹」「TCY30」等信息。
3. **本系统其余部分完全离线**：解析、规则判定、导出都在本机完成，本功能是**唯一**的出网点。
   因此"是否出网"这个开关的意义，比其他系统更大。

签署要确认的不是"能不能做"，而是：**允许外发哪些内容、发到哪个端点、对端可以留多久。**

## 2. 外发内容的精确清单

### 2.1 传输方式

```
POST  <HW_REVIEW_LLM_BASE_URL>/chat/completions
Header: Content-Type: application/json
Header: Authorization: Bearer <HW_REVIEW_LLM_API_KEY>
```

### 2.2 请求体里含有的数据

| 内容 | 来源 | 示例 |
|---|---|---|
| 系统提示词 | 代码内固定常量，**不含任何报告数据** | — |
| 待判定规则：`rule_id` | 模板 | `TR-17` |
| 待判定规则：`summary` | 模板 | `问题表述` |
| 待判定规则：`verifiable_requirement` | 模板 | `每条问题包含测试对象、测试条件、观察现象、实际结果` |
| 待判定规则：`required_materials` | 模板 | `问题清单` |
| 待判定规则：`confirmed_boundary` | 模板 | `[你说的] 固定按上述4要素判定` |
| **证据行文本** | **报告** | `[104] 测试结果`、`[2] TCY30` |
| **证据行所属原文件名** | **报告** | `TCY30 PP项目硬件测试报告(xPON)-V1.32.xls` |
| **证据行所属容器名** | **报告** | `sheet:首页`、`page:3` |

`证据行` 是归一化后的**纯文本**：每个非空文本块、每个非空表格单元格各占一行，
逐行以 `[序号] 文本` 的形式送出。模型只能引用**序号**，序号到文档结构地址的映射
保存在本机，因此模型无法伪造证据位置。

### 2.3 **不会**外发的数据

| 不外发 | 说明 |
|---|---|
| 原始文件本身 | 只发文本，不发 `.xls` / `.doc` / `.pdf` 的字节 |
| 本机绝对路径 | 样本根、工作区路径、存储路径 |
| 任务 / 模板标识 | `task_id`、`template_id`、`review_revision` 等 UUID |
| 用户身份 | 操作者、角色、会话标识 |
| 人工改判结论 | 审核人的判定、意见、历史修订 |
| 其他任务的数据 | 每次调用只包含当前任务的当前修订 |
| 空单元格 | 只送非空片段（实测 14.7 MB 的 XLS 只有 6,356 个非空片段） |

### 2.4 实测外发规模

| 样本 | 源文件 | 外发字符数 | 证据行数 |
|---|---:|---:|---:|
| S-01 | 14.7 MB | 82,713 | 6,356 |
| S-09 | 7.0 MB | 61,516 | 8,147 |
| S-17 | 10.7 MB | 57,763 | 7,766 |
| S-13 | 5.5 MB | 16,587 | 1,069 |
| S-14 | 10.6 MB | 16,727 | 1,735 |

约 5 万输入 token / 任务，单任务成本约 **$0.008**（输入 $0.15 / 1M）。

## 3. 对端与留存

| 项 | 值 |
|---|---|
| 端点 | `https://sgp-ai-platforms.skyworth-cloud.cn/v1` |
| 归属 | 集团企业云（**报告内容未出企业边界**） |
| 模型 | `deepseek-v4-flash`（推理模型） |
| 对端留存政策 | **未知，需本表签署人向端点归属方确认** ← 这是 OQ-06 的核心待补项 |
| 本系统留存 | 仅保存模型返回的结论文本与证据序号映射结果，**不保存请求体、不保存响应原文** |
| 日志 | 应用日志记录端点与模型名（启动时显式警告），**不记录报告文本** |

## 4. 控制手段（已实现，可供签署人核验）

| 控制 | 实现位置 |
|---|---|
| **默认关闭**，关闭时不发起任何网络请求 | `config.py` `HW_REVIEW_LLM_ENABLED=false` |
| 启用但缺少端点/密钥/模型 → **启动即失败**，不静默降级 | `config.py` |
| 启用时**启动日志显式警告**外发目标 | `api/app.py` `_semantic_judge` |
| 密钥只从环境变量读取，不入库、不入仓 | `config.py` |
| 外发体积上限（超出则整批转人工，**不截断**） | `HW_REVIEW_LLM_MAX_EVIDENCE_LINES` |
| 任何失败都降级为「待人工确认」，**永不**变成「符合」 | `services/semantic_judge.py` |
| 一次性完全停用 | 设 `HW_REVIEW_LLM_ENABLED=false` 并重启 |

## 5. 已知残余风险（签署人应知悉）

1. **对端留存未知**：这是唯一无法由本系统控制的风险。建议在签署前取得端点归属方的书面留存说明。
2. **报告文件名会被外发**：TR-07「报告版本及命名」这条规则本身要求检查文件名，因此文件名
   属于判定所需信息。若某个文件名本身敏感，需要单独例外处理。
3. **模型结论不可复现**：实测同一输入两次运行给出不同判定（详见
   [`verification.md`](verification.md) §7）。因此结果按修订冻结，且只有「待人工确认」项
   强制人工处理。
4. **推理模型的思维链由对端产生**：`reasoning_content` 属于对端模型内部产出，本系统只读
   `content`。
